ช่วงนี้ต้องเข้าใจอะไร

ช่วงนี้มีสามเรื่องที่ต่อกันเป็นทอด เรื่องแรกคือเครือข่าย ต้องเข้าใจว่าข้อมูลเดินทางยังไง ทำไมต้องแบ่งงานเป็นชั้น และทำไม NAT จึงยอมให้เครื่องข้างในออกไปได้แต่ไม่ให้คนข้างนอกเข้ามา เรื่องที่สองคือนิยามของ Cloud ซึ่งมีแก่นอยู่ที่การเช่าแทนการซื้อ และการแบ่งว่าใครดูแลชั้นไหน (IaaS, PaaS, SaaS) เรื่องที่สามคือ virtualization ซึ่งเป็นเทคโนโลยีที่ทำให้ Cloud ขายเครื่องเสมือนได้ในราคาถูก จุดที่ข้อสอบชอบถามลึกคือปัญหาของ CPU x86 กับวิธีแก้สามแบบ และความต่างระหว่าง VM กับ container

1. เปิดเว็บหนึ่งครั้ง ข้อมูลเดินทางยังไง

คอมพิวเตอร์บนอินเทอร์เน็ตติดต่อกันด้วยตัวเลขที่เรียกว่า IP address (Internet Protocol address) ซึ่งทำหน้าที่คล้ายบ้านเลขที่ ส่วนชื่อเว็บอย่าง google.com มีไว้ให้คนจำง่ายเท่านั้น พอเราพิมพ์ชื่อเว็บ browser จึงต้องถาม DNS (Domain Name System) ก่อนว่าชื่อนี้ตรงกับ IP อะไร เหมือนเปิดสมุดโทรศัพท์หาเบอร์จากชื่อ

ได้ IP แล้ว browser ต้องเปิดการเชื่อมต่อแบบ TCP (Transmission Control Protocol อธิบายในข้อ 3) กับปลายทางก่อน จากนั้นข้อมูลถูกหั่นเป็นชิ้นเล็กที่เรียกว่า packet แล้วส่งต่อเป็นทอด ๆ ผ่าน router ซึ่งเป็นอุปกรณ์ที่รับ packet แล้วส่งต่อไปเครือข่ายถัดไป เริ่มจาก router ในบ้าน ผ่าน ISP (Internet Service Provider ผู้ให้บริการอินเทอร์เน็ต) และ router อีกหลายตัว จนถึง edge ซึ่งเป็นทางเข้าเครือข่ายของ Google ที่อยู่ใกล้เราที่สุด จากนั้น server (เครื่องที่คอยรับคำขอแล้วส่งผลลัพธ์กลับ) จะประมวลผลคำขอแล้วส่งหน้าเว็บกลับมา ถ้าโจทย์ให้เรียงลำดับ ให้นึกว่าต้องรู้ที่อยู่ก่อน (DNS) แล้วจึงเปิดสาย (TCP) แล้วจึงส่งของ

2. ทำไมเครือข่ายต้องแบ่งงานเป็นชั้น

การเปิดเว็บหนึ่งครั้งมีงานหลายแบบปนกัน ทั้งตัดสินว่าจะขออะไร ดูแลให้ข้อมูลไปถึงครบ หาเส้นทาง และส่งสัญญาณจริงผ่านสายหรือคลื่นวิทยุ ถ้าโปรแกรมตัวเดียวทำทุกอย่าง วันที่เปลี่ยนจาก Wi-Fi เป็นสาย LAN (Local Area Network คือเครือข่ายในพื้นที่ใกล้ ๆ เช่น ในบ้านหรือในตึก) ก็อาจต้องแก้ browser ตามไปด้วย จึงแบ่งงานเป็นชั้น (layer) ให้แต่ละชั้นทำเรื่องเดียวและคุยกับชั้นที่อยู่ติดกันเท่านั้น ประโยชน์คือเปลี่ยนชั้นหนึ่งได้โดยไม่กระทบชั้นอื่น เหมือนคนส่งพัสดุไม่ต้องรู้ว่าบริษัทขนส่งจะขนด้วยรถหรือเครื่องบิน

แบบจำลองมีสองแบบ OSI (Open Systems Interconnection) แบ่ง 7 ชั้น ใช้อธิบายทางทฤษฎี ส่วน TCP/IP แบ่ง 4 ชั้นและเป็นแบบที่อินเทอร์เน็ตใช้จริง โดยรวมสามชั้นบนของ OSI เป็นชั้นเดียว และรวมสองชั้นล่างเป็นชั้นเดียว คำว่า protocol หมายถึงกติกาที่สองฝั่งตกลงกันไว้ว่าจะคุยกันด้วยรูปแบบไหน

ชั้นของ TCP/IPทำอะไรprotocol ตัวอย่าง
Applicationโปรแกรมตัดสินว่าจะคุยอะไรกันHTTP (HyperText Transfer Protocol ภาษาที่ browser คุยกับ web server) และ HTTPS ซึ่งเป็น HTTP แบบเข้ารหัส, DNS, FTP (File Transfer Protocol ใช้รับส่งไฟล์), SSH (Secure Shell ใช้รีโมตเข้าเครื่องอื่น)
Transportหั่นข้อมูล ใส่หมายเลข ดูแลให้ไปถึงครบTCP, UDP (User Datagram Protocol) ต่างกันอย่างไรดูข้อ 3
Internetใส่ที่อยู่ปลายทาง (IP) ให้ router เลือกเส้นทางIP, ICMP (Internet Control Message Protocol ใช้ส่งข้อความแจ้งสถานะของเครือข่าย เช่น ที่คำสั่ง ping ใช้)
Network Accessส่งสัญญาณจริงไปอุปกรณ์ตัวถัดไปEthernet (สาย LAN), Wi-Fi, fiber (สายใยแก้วนำแสง)

ถ้าโจทย์พูดเป็นเลขชั้นของ OSI ให้แปลงกลับเป็นงานของชั้นนั้น L7 (Application) คือตัวแอปที่ตัดสินว่าจะส่งข้อมูลอะไร L4 (Transport) คือ TCP กับ UDP รวมถึงเลข port (ข้อ 3) L3 (Network) คือ IP กับการเลือกเส้นทางของ router L2 (Data Link) คือการส่งต่อระหว่างอุปกรณ์ในเครือข่ายเดียวกัน เช่น Ethernet และ L1 (Physical) คือการส่งสัญญาณจริงเป็นบิตบนสายหรือคลื่น ส่วน L6 (Presentation) กับ L5 (Session) ซึ่งดูแลรูปแบบข้อมูลและการเปิดปิดช่วงการคุย ถูกรวมไว้ในชั้น Application ของ TCP/IP เลขชั้นเหล่านี้ใช้ต่อในช่วงหลัง เช่น อุปกรณ์ที่ทำงานที่ L4 ดูได้แค่ IP กับ port ส่วนอุปกรณ์ที่ L7 อ่านเนื้อหาของคำขอได้ด้วย

ข้อสอบชอบหลอกสองจุด ping ไม่ได้ใช้ TCP หรือ UDP แต่ใช้ ICMP ซึ่งอยู่ชั้น Internet และ DNS อยู่ชั้น Application เพราะ DNS ก็เป็นโปรแกรมที่ส่งคำถามและคำตอบหากันเหมือนแอปทั่วไป

3. TCP กับ UDP ต่างกันยังไง

ชั้น Transport มีให้เลือกสองตัวเพราะแอปต้องการไม่เหมือนกัน TCP เปิดการเชื่อมต่อก่อนส่ง ใส่หมายเลขทุก packet ชิ้นไหนหายก็ส่งใหม่ และเรียงให้ถูกลำดับ ข้อมูลจึงครบแน่นอนแต่ต้องเสียเวลารอ เหมาะกับหน้าเว็บ อีเมล และการโหลดไฟล์ UDP ส่งทันทีโดยไม่เปิดการเชื่อมต่อและไม่ส่งซ้ำ จึงเร็วแต่ข้อมูลอาจหาย เหมาะกับวิดีโอคอลและเกม เพราะภาพของวินาทีที่แล้วต่อให้ส่งมาใหม่ก็ไม่มีประโยชน์ วิธีตอบคือถามว่าข้อมูลหายได้ไหม ถ้าหายไม่ได้ตอบ TCP ถ้าหายได้บ้างแต่ช้าไม่ได้ตอบ UDP

ทั้งสองตัวใช้เลข port บอกว่าข้อมูลเป็นของโปรแกรมไหนในเครื่อง IP พาไปถึงเครื่องที่ถูก ส่วน port พาไปถึงโปรแกรมที่ถูก เหมือนบ้านเลขที่กับชื่อคนในบ้าน port ที่จะเจอบ่อยในช่วงหลังคือ 80 (เว็บ), 443 (เว็บแบบเข้ารหัส) และ 22 (SSH)

4. Private IP, Public IP และ NAT

IP รุ่นที่ใช้กันทั่วไปคือ IPv4 ซึ่งมีราว 4,300 ล้านหมายเลข ไม่พอแจกอุปกรณ์ทุกชิ้นในโลก ทางแก้คือกันบางช่วงไว้ให้ใช้ซ้ำกันได้ IP จึงแบ่งเป็นสองแบบ Private IP เป็นช่วงที่กันไว้ใช้ภายในบ้านหรือองค์กร เช่น 10.x.x.x และ 192.168.x.x ทุกบ้านใช้ซ้ำกันได้เพราะคนข้างนอกมองไม่เห็น ส่วน Public IP ไม่ซ้ำกันทั้งโลกและเข้าถึงได้จากทุกที่

ถ้ามือถือมีแค่ private IP คำตอบจาก Google จะกลับมาถึงได้ยังไง คำตอบคือ NAT (Network Address Translation) ตอนข้อมูลออกจากบ้าน router เปลี่ยนที่อยู่ผู้ส่งเป็น public IP ของตัวเอง และเปลี่ยนเลข port ของผู้ส่งเป็นเลขใหม่ด้วย แล้วจดคู่นั้นลงตารางว่าการเชื่อมต่อนี้เป็นของเครื่องไหน พอคำตอบกลับมาที่ port นั้นก็เปิดตารางแล้วส่งต่อให้ถูกเครื่อง หลายเครื่องจึงใช้ public IP เดียวกันได้

ผลพลอยได้ที่สำคัญที่สุดคือ คนข้างนอกเปิดการเชื่อมต่อเข้ามาเองไม่ได้ เพราะในตารางไม่มีรายการว่าจะส่งให้ใคร packet นั้นจึงถูกทิ้ง หลักคิด "เริ่มจากข้างในได้ เริ่มจากข้างนอกไม่ได้" นี้จะกลับมาอีกในช่วงที่ 2 ในชื่อ NAT Gateway

5. Cloud Computing คืออะไร

ก่อนมี Cloud บริษัทต้องซื้อ server เอง จ่ายเงินก้อนใหญ่ล่วงหน้าและต้องเดาขนาดให้ถูก ซื้อเล็กไปเว็บล่มตอนคนเข้าเยอะ ซื้อใหญ่ไปก็เสียเงินกับเครื่องที่ว่าง Cloud Computing แก้ด้วยการให้เช่าทรัพยากรคอมพิวเตอร์ผ่านอินเทอร์เน็ตได้ทันทีที่ต้องการ และจ่ายตามที่ใช้จริง (pay-as-you-go) ของที่เช่าได้มีตั้งแต่ VM (เครื่องเสมือน อธิบายในข้อ 10) ที่เก็บข้อมูล ฐานข้อมูล ไปจนถึงบริการ AI ในทางบัญชี นี่คือการเปลี่ยนจาก CapEx (เงินลงทุนก้อนใหญ่ล่วงหน้า) เป็น OpEx (ค่าใช้จ่ายที่จ่ายไปเรื่อย ๆ ตามการใช้งาน เหมือนค่าไฟ) และงานดูแลฮาร์ดแวร์ย้ายไปเป็นภาระของผู้ให้บริการ

เบื้องหลังของ Cloud คือ server หลายพันเครื่องใน data center (อาคารที่รวม server จำนวนมากไว้ พร้อมไฟฟ้าสำรองและระบบทำความเย็น) หลายแห่งทั่วโลกที่เชื่อมกันด้วยเครือข่าย ถ้ามี server เครื่องเดียวจะเจอทั้งปัญหา latency (คนที่อยู่ไกลต้องรอนาน) และ single point of failure (จุดเดียวพังแล้วทั้งระบบพังตาม) การกระจายเครื่องแก้ได้ทั้งสองข้อ แต่ server ที่กระจายกันอยู่จะทำงานร่วมกันเหมือนเครื่องเดียวได้ก็ต้องมีเครือข่ายที่ดี สไลด์จึงสรุปว่า "Computing is Networking"

6. ลักษณะ 5 ข้อของ Cloud ตาม NIST

NIST (National Institute of Standards and Technology สถาบันมาตรฐานและเทคโนโลยีแห่งชาติของสหรัฐฯ) กำหนดว่าระบบที่จะเรียกว่า Cloud ได้ต้องมีครบห้าข้อ ถ้าขาดข้อใด เช่น ต้องโทรขอให้เจ้าหน้าที่เปิดเครื่องให้ ก็ยังไม่นับเป็น Cloud ข้อสอบมักเล่าสถานการณ์แล้วถามว่าตรงกับข้อไหน

ลักษณะความหมายตัวอย่าง
On-demand self-serviceขอใช้ได้เองทันที ไม่ต้องรอคนอนุมัติกดสร้าง VM จากหน้าเว็บได้เลย
Broad network accessเข้าถึงผ่านเครือข่ายได้จากทุกอุปกรณ์จัดการจากโน้ตบุ๊กหรือมือถือก็ได้
Resource poolingรวมทรัพยากรเป็นกองกลางให้ลูกค้าหลายรายใช้ร่วมกัน (multi-tenant)VM ของหลายบริษัทอยู่บนเครื่องจริงเครื่องเดียวกัน
Rapid elasticityเพิ่มหรือลดทรัพยากรได้เร็วตามปริมาณงานช่วงลดราคาเพิ่มเครื่อง จบงานลดลง
Measured serviceวัดการใช้งานและคิดเงินตามจริงบิลบอกว่าใช้ CPU กี่ชั่วโมง

คู่ที่สับสนบ่อยคือ resource pooling กับ rapid elasticity ข้อแรกพูดถึงการใช้เครื่องร่วมกันของลูกค้าหลายราย ข้อหลังพูดถึงการขยายและหดขนาดตามงาน

7. IaaS, PaaS และ SaaS

แอปหนึ่งตัวอาศัยของหลายชั้นซ้อนกัน ล่างสุดคือฮาร์ดแวร์และเครือข่าย ถัดมาคือ OS (ระบบปฏิบัติการ เช่น Linux หรือ Windows) ถัดมาคือ runtime (ซอฟต์แวร์ที่แอปต้องใช้ตอนรัน เช่น Python) กับ middleware (ซอฟต์แวร์ตัวกลางที่เชื่อมแอปกับส่วนอื่น เช่น ตัวเชื่อมต่อฐานข้อมูล) และบนสุดคือแอปกับข้อมูล สิ่งที่ทำให้บริการ Cloud สามแบบต่างกันมีอยู่เรื่องเดียว คือผู้ให้บริการดูแลให้ถึงชั้นไหน แล้วเราต้องดูแลเองตั้งแต่ชั้นไหน

แบบย่อมาจากผู้ให้บริการให้อะไรเราดูแลอะไรตัวอย่าง
IaaSInfrastructure as a Serviceเครื่องเปล่า เครือข่าย ดิสก์ตั้งแต่ OS ขึ้นไปทั้งหมด รวมถึงลง patch (ตัวแก้ช่องโหว่ของซอฟต์แวร์) เองAmazon EC2 (เช่า VM)
PaaSPlatform as a Serviceเครื่อง + OS + runtimeแค่โค้ดกับข้อมูลอัปโค้ดขึ้นไปแล้วรันได้เลย
SaaSSoftware as a Serviceซอฟต์แวร์พร้อมใช้แค่ใช้งาน ผู้ให้บริการดูแลทุกชั้นตามสไลด์ (ดูข้อควรระวังใต้ภาพ)Gmail

เปรียบง่าย ๆ ว่า IaaS คือเช่าที่ดินเปล่าแล้วสร้างบ้านเอง PaaS คือเช่าห้องที่ต่อน้ำไฟไว้แล้ว SaaS คือห้องโรงแรมที่หิ้วกระเป๋าเข้าไปอยู่ได้เลย จุดที่ต้องระวังคือ SaaS ถ้าโจทย์ถามตามตารางของสไลด์ ให้ตอบว่าผู้ให้บริการดูแลทุกชั้นรวมถึงแอปกับข้อมูล แต่ถ้าถามในมุมความปลอดภัยของข้อมูล ให้ตอบว่าเป็นความรับผิดชอบร่วมกัน เพราะถ้าเราตั้งรหัสผ่านง่าย ๆ หรือแชร์ไฟล์ให้คนผิด ผู้ให้บริการห้ามเราไม่ได้

8. Public cloud, Private cloud และ Hybrid cloud

Public cloud คือแบบที่ผู้ให้บริการเป็นเจ้าของเครื่องและเปิดให้ลูกค้าจำนวนมากเช่าร่วมกัน ขยายได้แทบไม่จำกัดและจ่ายตามใช้ Private cloud คือแบบที่องค์กรเดียวใช้ผู้เดียว มักตั้งใน data center ขององค์กรเอง ควบคุมได้เต็มที่และทำตามกฎหมายง่าย แต่ต้องลงทุนและดูแลเอง Hybrid cloud คือการใช้ทั้งสองแบบแล้วเชื่อมถึงกัน เช่น ธนาคารเก็บข้อมูลลูกค้าไว้ใน Private cloud แต่วางเว็บประชาสัมพันธ์ไว้บน Public cloud

ศัพท์ที่มากับเรื่องนี้มีสองคำ data sovereignty คือการคุมได้ว่าข้อมูลเก็บอยู่ในประเทศไหนให้ตรงตามกฎหมาย และ cloud bursting คือส่งงานส่วนที่ล้นจาก Private cloud ไปทำบน Public cloud ชั่วคราวช่วงที่คนใช้เยอะ

9. Region และ Availability Zone

Region คือพื้นที่ทางภูมิศาสตร์ที่ผู้ให้บริการตั้ง data center ไว้ เช่น Singapore เราเลือก Region จากสองเหตุผล คือยิ่งใกล้ผู้ใช้ latency ยิ่งต่ำ และกฎหมายบางประเทศบังคับให้เก็บข้อมูลไว้ในประเทศ

ใน Region หนึ่งแบ่งเป็นหลาย Availability Zone (AZ) แต่ละ AZ คือ data center ที่แยกกันจริง มีไฟฟ้า ระบบทำความเย็น และเครือข่ายของตัวเอง ห่างกันพอที่ภัยที่หนึ่งจะไม่ลามไปอีกที่ แต่ใกล้กันพอที่จะส่งข้อมูลหากันได้เร็ว ถ้าทำสำเนาระบบไว้หลาย AZ แล้ว AZ หนึ่งล่ม ผู้ใช้ก็แทบไม่รู้สึกอะไร Region จึงเหมือนจังหวัด ส่วน AZ คืออาคารหลายหลังในจังหวัดนั้นที่ใช้ไฟคนละสาย ประโยชน์ของการกระจายข้าม AZ คือ high availability (พร้อมใช้ต่อเนื่อง), fault tolerance (ความเสียหายจำกัดอยู่ที่เดียว), disaster recovery (กู้คืนหลังภัยพิบัติได้) และซ่อมทีละ AZ ได้โดยไม่ต้องปิดทั้งระบบ

10. Virtualization และ Hypervisor

ก่อนมี virtualization องค์กรใช้ server หนึ่งเครื่องต่องานหนึ่งอย่าง แต่ละเครื่องใช้ CPU จริงแค่ส่วนน้อย ที่เหลือว่างแต่ยังกินค่าไฟและพื้นที่เต็มเครื่อง virtualization คือการสร้าง CPU หน่วยความจำ ดิสก์ และเครือข่าย "เสมือน" ขึ้นจากฮาร์ดแวร์จริง เพื่อแบ่งเครื่องจริงหนึ่งเครื่องเป็นหลาย VM (Virtual Machine) แต่ละ VM มี OS ของตัวเองและทำงานแยกกันเหมือนคนละเครื่อง เครื่องจริงจึงถูกใช้คุ้มขึ้นมาก นี่คือเหตุที่ Cloud ขาย VM ได้ถูก

ซอฟต์แวร์ที่แบ่งเครื่องจริงเป็น VM เรียกว่า hypervisor หรืออีกชื่อหนึ่งคือ VMM (Virtual Machine Monitor) ถ้าโจทย์ใช้คำไหนก็หมายถึงสิ่งเดียวกัน hypervisor อยู่ระหว่างฮาร์ดแวร์กับ OS ของแต่ละ VM (เรียกว่า guest OS) ทุกครั้งที่ VM จะใช้ทรัพยากรจริงต้องผ่าน hypervisor เหมือนผู้จัดการอาคารที่ไม่ให้ห้องหนึ่งไปใช้ของอีกห้อง

Hypervisor มีสองแบบ แบบแรกคือ Type 1 (bare-metal) ซึ่งติดตั้งบนฮาร์ดแวร์โดยตรง ไม่มี OS อื่นคั่น จึงเร็วและปลอดภัยที่สุด ตัวที่รู้จักกันคือ VMware ESXi, Xen, KVM และ Hyper-V ซึ่งผู้ให้บริการ Cloud ทุกเจ้าใช้แบบนี้ ส่วนแบบที่สองคือ Type 2 (hosted) ซึ่งเป็นโปรแกรมที่ลงบน OS ที่มีอยู่แล้ว (เรียกว่า host OS) ติดตั้งง่ายแต่ช้ากว่าเพราะต้องผ่าน host OS อีกชั้น เหมาะกับทดลองบนโน้ตบุ๊ก เช่น VirtualBox จำสั้น ๆ ว่า Type 1 ใช้กับระบบจริง Type 2 ใช้บนเครื่องส่วนตัว

ในปัจจุบัน hypervisor ที่ครองตลาด Cloud คือ KVM ซึ่งเป็นส่วนหนึ่งของ Linux เหตุผลคือ KVM ได้ของที่ Linux มีอยู่แล้วมาใช้ฟรีทั้งหมด ทั้งระบบจัดเวลา CPU ระบบจัดการหน่วยความจำ และระบบความปลอดภัย ทุกครั้งที่ Linux ปรับปรุงส่วนเหล่านี้ KVM ก็ดีขึ้นตามไปด้วยโดยไม่ต้องเขียนเอง

11. เงื่อนไขของ Popek และ Goldberg

Popek และ Goldberg เป็นนักวิจัยสองคนที่วางทฤษฎีพื้นฐานของ virtualization ทั้งคู่กำหนดว่า hypervisor ที่ถูกต้องต้องมีสามข้อ ซึ่งสไลด์เรียกว่า VMM requirements ข้อแรก Equivalence คือโปรแกรมใน VM ต้องได้ผลเหมือนรันบนเครื่องจริง ข้อสอง Resource Control คือ hypervisor ต้องคุมทรัพยากรจริงทั้งหมด VM ใช้เกินส่วนของตัวเองไม่ได้ และข้อสาม Efficiency คือคำสั่งส่วนใหญ่ต้องรันบน CPU จริงได้ตรง ๆ ไม่อย่างนั้นจะช้าจนใช้ไม่ได้

ความยากอยู่ที่ระบบสิทธิ์ของ CPU ซึ่งแบ่งเป็นชั้นที่เรียกว่า ring Ring 0 มีสิทธิ์สูงสุด เป็นที่อยู่ของ kernel (แกนกลางของ OS ที่คุมฮาร์ดแวร์) ส่วนโปรแกรมทั่วไปอยู่ Ring 3 คำสั่งที่ทำได้เฉพาะใน Ring 0 เรียกว่า privileged instruction ถ้าเรียกจาก ring อื่น CPU จะหยุดแล้วส่งเรื่องไปให้ Ring 0 ตัดสิน เรียกว่า trap

ลองนึกภาพบริษัทหนึ่ง Ring 0 คือผู้จัดการที่ถือกุญแจห้องสำคัญทุกห้อง ส่วน Ring 3 คือพนักงานทั่วไป ถ้าพนักงานจะทำเรื่องสำคัญ เช่น เปิดห้องเก็บเงิน ระบบไม่ยอมให้ทำเอง แต่จะส่งเรื่องขึ้นไปให้ผู้จัดการตัดสิน การส่งเรื่องขึ้นไปนี้แหละคือ trap

ปัญหาคือ guest OS ถูกเขียนมาให้อยู่ Ring 0 แต่ตำแหน่งนั้นต้องเป็นของ hypervisor วิธีดั้งเดิมจึงย้าย guest ไปอยู่ ring ที่มีสิทธิ์น้อยกว่า (Ring 1) เมื่อ guest เรียกคำสั่ง privileged ก็จะ trap แล้ว hypervisor รับไปทำแทน วิธีนี้เรียกว่า trap-and-emulate ในภาพบริษัทเดิม guest OS คือหัวหน้าแผนกที่ถูกผู้จัดการตัวจริง (hypervisor) แอบลดสิทธิ์เป็นพนักงานโดยไม่รู้ตัว พอทำเรื่องสำคัญ เรื่องก็ถูกส่งขึ้นไปให้ผู้จัดการตัวจริงจัดการแทน

แต่วิธีนี้ได้ผลก็ต่อเมื่อคำสั่งอันตรายทุกตัว trap จริง คำสั่งที่อ่านหรือเปลี่ยนสถานะสำคัญของเครื่องเรียกว่า sensitive instruction Popek และ Goldberg จึงพิสูจน์ต่อจากเงื่อนไขสามข้อว่า CPU จะ virtualize แบบดั้งเดิมได้ก็ต่อเมื่อ sensitive instruction ทุกตัวเป็น privileged instruction ด้วย ถ้ามีตัวไหนไม่ trap hypervisor ก็จะไม่รู้เลยว่า guest เรียกคำสั่งนั้น

x86 คือตระกูล CPU ของ Intel และ AMD ที่ใช้ในคอมพิวเตอร์และ server ส่วนใหญ่ รุ่นเก่าของตระกูลนี้ไม่ผ่านเงื่อนไขข้างต้น เพราะมีคำสั่ง sensitive บางตัวที่รันนอก Ring 0 แล้วไม่ trap แต่ทำงานผิดไปเงียบ ๆ ไม่มี error ใด ๆ hypervisor จึงดักไม่ได้ เหมือนพนักงานกดปุ่มปิดสัญญาณเตือนของตึก ปุ่มไม่ทำงานเพราะสิทธิ์ไม่พอแต่ไม่มีอะไรบอก พนักงานจึงทำงานต่อโดยเข้าใจผิดว่าปิดไปแล้ว ข้อนี้ออกสอบบ่อย และเป็นที่มาของวิธีแก้สามแบบในข้อถัดไป

12. สามวิธีแก้ปัญหาของ x86

Full virtualization ไม่แก้ guest OS เลย แต่ให้ hypervisor ตรวจโค้ดของ guest ก่อนรัน เจอคำสั่ง sensitive ที่ไม่ trap ก็เขียนใหม่ให้กลายเป็นการเรียก hypervisor เรียกว่า binary translation ข้อดีคือรัน OS ได้ทุกตัว ข้อเสียคือช้าลงเพราะต้องตรวจและแปลง

Para-virtualization แก้ kernel ของ guest ให้รู้ตัวว่าอยู่บน hypervisor เมื่อต้องใช้สิทธิ์สูงก็เรียก hypervisor ตรง ๆ ด้วย hypercall แทนการรอให้ถูกดัก จึงเร็วเกือบเท่าเครื่องจริง แต่ต้องแก้ kernel ของ guest ได้ Linux มีส่วนนี้ติดมาใน kernel อยู่แล้ว ส่วน OS ที่คนนอกแก้ kernel เองไม่ได้อย่าง Windows ต้องลง driver พิเศษเพิ่มแทน (driver คือโปรแกรมที่ OS ใช้คุยกับอุปกรณ์) Xen เป็นผู้บุกเบิกวิธีนี้

Hardware-assisted virtualization แก้ที่ตัว CPU (Intel VT-x, AMD-V) โดยเพิ่มโหมดให้ hypervisor กับ guest อยู่คนละโหมด guest จึงได้อยู่ Ring 0 ของตัวเองจริง แต่เมื่อเรียกคำสั่งอันตราย CPU จะสลับไปให้ hypervisor จัดการเองอัตโนมัติ (สลับออกเรียกว่า VMEXIT สลับกลับเรียกว่า VMENTER) วิธีนี้ไม่ต้องแก้ guest และยังเร็ว จึงเป็นวิธีที่ใช้กันในปัจจุบัน

สไลด์ยังมีอีกชุดที่จัดเฉพาะเทคนิคของ CPU virtualization เป็นสามแบบ คือ trap-and-emulate (วิธีดั้งเดิมในข้อ 11 เร็วปานกลาง), binary translation (เร็วปานกลางถึงสูง) และ hardware-assisted (เร็วที่สุด) ชุดนี้ต่างจากชุดแรกตรงที่มี trap-and-emulate แทน para-virtualization ถ้าโจทย์ถามถึงเทคนิค CPU virtualization สามแบบ ให้ตอบชุดนี้

13. Virtualization มีหลายระดับ

นอกจากจำลองเครื่องทั้งเครื่อง ยังเลือกจำลองได้หลายระดับ หลักคือยิ่งต้องใช้ซอฟต์แวร์ทำงานแทนของจริงมาก ยิ่งช้า ระดับ ISA (Instruction Set Architecture) จำลองชุดคำสั่งของ CPU ทั้งชุดเพื่อรันโปรแกรมของ CPU อีกแบบ จึงช้าที่สุดเพราะต้องแปลทีละคำสั่ง ระดับ HAL (Hardware Abstraction Layer) จำลองฮาร์ดแวร์ทั้งเครื่องให้รัน OS ได้ ซึ่งก็คือ VM ส่วนระดับ OS ไม่จำลองฮาร์ดแวร์เลย แต่ให้หลายโปรแกรมใช้ kernel ร่วมกันโดยแยกพื้นที่ ซึ่งก็คือ container (ข้อ 17) จึงแทบไม่ช้าลง

สองระดับบนสุดจำลองแค่สิ่งที่โปรแกรมเรียกใช้ ระดับ library จำลอง API (Application Programming Interface ชุดฟังก์ชันที่ OS เปิดให้โปรแกรมเรียกใช้) ของ OS อีกตัว เช่น ทำให้โปรแกรมของ Windows รันบน Linux ได้ ส่วนระดับ application จำลอง runtime ของภาษา เช่น JVM (Java Virtual Machine) ที่ทำให้โปรแกรม Java ตัวเดียวรันได้ทุกเครื่อง

ระดับจำลองอะไรช้าลงแค่ไหนตัวอย่าง
ISAชุดคำสั่งของ CPU ทั้งชุดช้ามากรันโปรแกรมของ CPU อีกแบบ

Applicationruntime ของภาษาปานกลางJVM

ระดับที่สำคัญต่อ Cloud คือระดับ HAL (VM) กับระดับ OS (container) ข้อสอบชอบถามว่า Docker (เครื่องมือสร้างและรัน container ที่นิยมที่สุด) อยู่ระดับไหน คำตอบคือระดับ OS

14. การจำลองหน่วยความจำ

โปรแกรมทั่วไปไม่เห็นตำแหน่งจริงใน RAM แต่เห็นที่อยู่เสมือน (virtual address) ที่ OS แจกให้ ทุกโปรแกรมจึงรู้สึกเหมือนมีหน่วยความจำเป็นของตัวเองทั้งก้อน และไปเขียนทับของโปรแกรมอื่นไม่ได้ OS แบ่งหน่วยความจำเป็นก้อนขนาดเท่ากันที่เรียกว่า page แล้วใช้ตาราง page table จดว่าที่อยู่เสมือนแต่ละก้อนตรงกับตำแหน่งจริงตรงไหน ใน VM การแปลงต้องทำสองขั้น เพราะ "RAM จริง" ที่ guest เห็นก็ยังเป็นของปลอมที่ hypervisor สร้าง ขั้นแรก guest แปลงที่อยู่ของโปรแกรมเป็นตำแหน่งที่ guest คิดว่าจริง ขั้นที่สอง hypervisor แปลงต่อเป็นตำแหน่งบน RAM จริง

เทียบได้กับบริษัทที่เช่าพื้นที่ในตึก คนในบริษัทเรียกห้องหนึ่งว่า "ห้องประชุม A" ผังของบริษัทบอกว่าห้องประชุม A คือห้องเช่าห้องที่ 3 ของบริษัท แต่ผังของตึกบอกว่าห้องเช่าห้องที่ 3 ของบริษัทนี้คือห้อง 1205 คนส่งของที่ได้แค่ชื่อ "ห้องประชุม A" จึงต้องเปิดผังสองฉบับต่อกันจึงจะถึงห้องจริง ผังของบริษัทคือ page table ของ guest ส่วนผังของตึกคือตารางของ hypervisor

วิธีเก่าคือ shadow page table ซึ่ง hypervisor ทำตารางเงารวมสองขั้นไว้ แต่ต้องคอยอัปเดตทุกครั้งที่ guest แก้ตารางของตัวเอง จึงช้า วิธีใหม่คือ EPT/NPT (Extended Page Tables ของ Intel / Nested Page Tables ของ AMD) ซึ่งให้ CPU ค้นตารางทั้งสองขั้นเองโดยไม่ต้องเรียก hypervisor จึงเร็วกว่ามาก (เป็นแนวคิดเดียวกับ hardware-assisted ในข้อ 12 คือย้ายงานจากซอฟต์แวร์ไปให้ CPU) ในตัวอย่างตึก shadow page table คือยามที่ทำผังรวมไว้ให้ว่าห้องประชุม A คือห้อง 1205 แต่ต้องตามแก้ทุกครั้งที่บริษัทสลับห้อง ส่วน EPT/NPT คือให้คนส่งของ (CPU) เปิดผังสองฉบับเองได้เร็ว ๆ โดยไม่ต้องพึ่งยาม

ผู้ให้บริการยังขาย RAM ได้มากกว่าที่เครื่องมีจริง เรียกว่า overcommit เพราะ VM ส่วนใหญ่ไม่ได้ใช้ RAM เต็มที่ขอไว้ตลอดเวลา เทคนิคแรกคือ memory ballooning ซึ่งลง driver ตัวเล็ก ๆ ไว้ใน guest เมื่อ hypervisor ต้องการ RAM คืน driver จะ "พองลูกโป่ง" ขอจอง RAM จาก guest เพิ่ม guest จึงต้องย้ายข้อมูลที่ไม่ค่อยใช้ไปพักบนดิสก์ แล้ว hypervisor เอา RAM ส่วนนั้นไปให้ VM อื่น เทคนิคที่สองคือ KSM (Kernel Same-page Merging) ซึ่งรวมหน้าหน่วยความจำที่เหมือนกันในหลาย VM ไว้ชุดเดียว เช่น โค้ด OS ตัวเดียวกันที่อยู่ในทุก VM ถ้า VM ตัวไหนจะเขียนทับหน้านั้น hypervisor ก็แยกสำเนาให้ VM ตัวนั้นทันที (เรียกว่า copy-on-write) VM อื่นจึงไม่โดนผลกระทบ

การคำนวณ overcommit คือ RAM ที่ขายไปทั้งหมดหารด้วย RAM จริง เช่น server มี RAM 256 GB รัน VM ขนาด 8 GB จำนวน 50 เครื่อง ขายไป 8 × 50 = 400 GB อัตราจึงเป็น 400 ÷ 256 ≈ 1.56 : 1

15. การจำลอง I/O

I/O คือการรับส่งข้อมูลกับอุปกรณ์อย่างดิสก์และการ์ดเครือข่าย เป็นจุดที่ช้าที่สุดของ virtualization เพราะ VM หลายตัวต้องใช้อุปกรณ์จริงชุดเดียวกัน วิธีจัดการมีสามแบบ และหลักเดิมยังใช้ได้ คือยิ่งใช้ซอฟต์แวร์จำลองฮาร์ดแวร์น้อย ยิ่งเร็ว

Full emulation ใช้ซอฟต์แวร์จำลองการ์ดรุ่นที่มีขายจริง guest ใช้ driver ปกติได้ แต่ทุกการรับส่งต้องผ่านการจำลองจึงช้า virtio (virtual I/O) ให้ guest ใช้ driver พิเศษที่รู้ตัวว่าอยู่ใน VM แล้วส่งข้อมูลกับ hypervisor ผ่านหน่วยความจำร่วมโดยตรง จึงเร็ว (เป็นแนวคิด para-virtualization แต่ใช้กับ I/O) SR-IOV (Single Root I/O Virtualization) ให้การ์ดจริงแบ่งตัวเองเป็นหลายการ์ดย่อยแล้วยกให้ VM ใช้ตรง ๆ โดยไม่ผ่าน hypervisor จึงเร็วใกล้เครื่องจริง วิธีที่คล้ายกันคือ passthrough ซึ่งยกอุปกรณ์จริงทั้งชิ้นให้ VM ตัวเดียวใช้ไปเลย

16. Xen: Dom0 และ DomU

Xen ตั้งใจทำ hypervisor ให้เล็กที่สุด เพราะโค้ดยิ่งน้อยยิ่งมีจุดให้พังหรือถูกโจมตีน้อย ตัว hypervisor จึงทำแค่จัดเวลา CPU กับจัดการหน่วยความจำ ส่วน driver ของอุปกรณ์และเครื่องมือจัดการย้ายไปอยู่ใน VM พิเศษชื่อ Dom0 (Domain 0 เพราะ Xen เรียก VM แต่ละตัวว่า domain) ซึ่งเป็น VM ตัวเดียวที่แตะฮาร์ดแวร์จริงได้ ส่วน VM ของลูกค้าเรียกว่า DomU (U ย่อมาจาก unprivileged คือไม่มีสิทธิ์พิเศษ)

แนวคิดทำ hypervisor ให้เล็กแล้วย้ายงานอื่นออกไปไว้ข้างนอกแบบนี้เรียกว่า microkernel ตรงข้ามกับแบบ monolithic อย่าง VMware ESXi ที่รวม driver และงานจัดการทุกอย่างไว้ในตัว hypervisor เอง ข้อดีของ microkernel คือส่วนที่ต้องไว้ใจว่าไม่มีช่องโหว่ (เรียกว่า trusted computing base) เล็กกว่ามาก

เมื่อ DomU จะใช้ดิสก์หรือเครือข่าย จะใช้ split driver คือ driver ที่ผ่าเป็นสองครึ่ง ครึ่งหน้าใน DomU วางข้อมูลลงหน่วยความจำร่วม แล้วครึ่งหลังใน Dom0 มาหยิบไปส่งให้อุปกรณ์จริง ตัว hypervisor ไม่ต้องอยู่บนเส้นทางของข้อมูลเลย

17. Container ต่างจาก VM ยังไง

VM ทุกตัวต้องมี guest OS ของตัวเอง ถ้ามีแอปเล็ก ๆ 100 ตัวแยกคนละ VM ก็ต้องมี OS 100 ชุด กิน RAM มากและเปิดเครื่องช้า container แก้ด้วยการให้ทุกแอปใช้ kernel ของเครื่องหลักตัวเดียวกัน แต่แยกพื้นที่ด้วยสองกลไกของ Linux คือ namespace กับ cgroups โดย namespace ทำให้แต่ละ container มองเห็นแค่ process (โปรแกรมที่กำลังรันอยู่) เครือข่าย และไฟล์ของตัวเอง เหมือนอยู่ในเครื่องแยก ส่วน cgroups (control groups) จำกัดว่าแต่ละ container ใช้ CPU และ RAM ได้ไม่เกินเท่าไร จำง่าย ๆ ว่า namespace คุมสิ่งที่มองเห็น cgroups คุมปริมาณที่ใช้ได้ Docker และ Kubernetes (ระบบจัดการ container จำนวนมาก) ทำงานด้วยกลไกนี้

ข้อสอบชอบหลอกว่า container ปลอดภัยกว่าเพราะใหม่กว่า ซึ่งไม่จริง container ใช้ kernel ร่วมกัน ถ้า kernel มีช่องโหว่ ผู้โจมตีอาจข้ามจาก container หนึ่งไปอีกตัวได้ ระบบจริงจึงมักใช้ซ้อนกัน คือใช้ VM แยกลูกค้าเพื่อความปลอดภัย แล้วรัน container หลายตัวในแต่ละ VM เพื่อใช้ทรัพยากรให้คุ้ม

18. ประโยชน์ของ virtualization

ด้านค่าใช้จ่าย รวม VM หลายตัวไว้ในเครื่องจริงเครื่องเดียวได้ (server consolidation) ประหยัดทั้งฮาร์ดแวร์ ค่าไฟ และพื้นที่ ด้านความเสถียร ถ้า VM ตัวหนึ่งพังก็ไม่ลามไปตัวอื่น (isolation) และบันทึกสถานะเครื่องไว้แล้วย้อนกลับได้ (snapshot) ด้านความยืดหยุ่น ปรับ CPU หรือ RAM และโคลนเครื่องใหม่ได้ในไม่กี่นาที และเพราะ VM มองเห็นแต่ฮาร์ดแวร์เสมือน จึงไม่ผูกกับ CPU หรือการ์ดรุ่นใดรุ่นหนึ่ง (hardware abstraction) ย้ายไปรันบนเครื่องจริงต่างรุ่นได้

ข้อที่สไลด์เน้นคือ live migration หมายถึงการย้าย VM ที่กำลังทำงานไปเครื่องจริงอีกเครื่องโดยระบบหยุดไปไม่ถึงวินาที ผู้ให้บริการใช้วิธีนี้ย้าย VM ออกไปก่อนเอาเครื่องจริงไปซ่อม ลูกค้าจึงไม่รู้ตัวเลย

ประโยชน์เหล่านี้รวมกันทำให้ทั้ง data center สั่งงานด้วยซอฟต์แวร์ได้ (สไลด์เรียกว่า software-defined data center) เมื่อเครื่องจริงทุกเครื่องรัน hypervisor ระบบจัดการกลางก็ทำงานอัตโนมัติได้หลายอย่าง เช่น ย้าย VM จากเครื่องที่งานหนักไปเครื่องที่ว่าง (workload balancing) เปิด VM ชุดเดิมขึ้นใหม่บนเครื่องอื่นภายในไม่กี่วินาทีเมื่อเครื่องจริงพัง (high availability) ส่งสำเนา snapshot ไปเก็บอีก data center เผื่อเกิดภัย (disaster recovery) และสร้าง VM เพิ่มทีละมาก ๆ ช่วงคนใช้เยอะแล้วลบทิ้งเมื่องานลด (elastic scaling) นี่คือสะพานจาก virtualization สู่ Cloud ถ้าไม่มี virtualization ผู้ให้บริการก็ต้องติดตั้งเครื่องจริงด้วยมือทีละเครื่อง

จุดที่ต้องแยกให้ออกคือ live migration ใช้ได้เฉพาะตอนที่เครื่องต้นทางยังทำงานอยู่ เพราะต้องคัดลอกสถานะของ VM ที่กำลังรันออกมา ถ้าเครื่องจริงพังไปแล้ว ระบบทำได้แค่เปิด VM ขึ้นใหม่บนเครื่องอื่น (restart) ซึ่งงานที่ค้างอยู่ใน RAM ตอนนั้นจะหายไป ไม่ใช่การย้ายแบบไม่สะดุด

19. บริการ Compute และ Storage

บริการเช่า VM แต่ละเจ้าเรียกชื่อต่างกันแต่เป็นของอย่างเดียวกัน เช่น AWS (Amazon Web Services) เรียกว่า EC2 ส่วนที่เก็บข้อมูลมีสามแบบ ใช้ต่างกันตามลักษณะข้อมูล ให้นึกถึงร้านค้าออนไลน์ที่ต้องเก็บฐานข้อมูลคำสั่งซื้อ รูปสินค้า และโฟลเดอร์ที่ server หลายเครื่องต้องเปิดพร้อมกัน

แบบลักษณะใช้กับตัวอย่างบน AWS
Block storageดิสก์ที่ต่อกับเครื่องเดียว เหมือนฮาร์ดดิสก์ในคอม เร็วฐานข้อมูลบน VMEBS
Object storageเก็บไฟล์เป็นก้อน เรียกผ่าน URL ได้จากทุกที่ ขยายไม่จำกัดรูปภาพ วิดีโอ ไฟล์ที่เขียนครั้งเดียวอ่านบ่อยS3
File storageโฟลเดอร์ที่หลายเครื่องเปิดพร้อมกันได้โฟลเดอร์ที่ web server หลายเครื่องใช้ร่วมกันEFS

วิธีแยกคือถามว่าใครใช้ข้อมูลและใช้ยังไง ถ้าโจทย์พูดถึงหลายเครื่องใช้โฟลเดอร์เดียวกัน ให้ตอบ File storage ไม่ใช่ Block storage เพราะ block ต่อได้ทีละเครื่อง

ทวนก่อนสอบ

ถ้าต้องเล่าช่วงนี้ให้จบในไม่กี่ประโยค เริ่มจากเครือข่าย ซึ่งแบ่งงานเป็นชั้นเพื่อให้เปลี่ยนชั้นหนึ่งได้โดยไม่กระทบชั้นอื่น ส่วน NAT ให้เครื่องข้างในเป็นฝ่ายเริ่มคุยได้ แต่ไม่ให้คนข้างนอกเริ่ม

ต่อมาคือ Cloud ซึ่งเป็นการเช่าทรัพยากรแบบจ่ายตามใช้ แบ่งความรับผิดชอบตามชั้น (IaaS ดูแลเองมากสุด SaaS น้อยสุด) และกระจายระบบข้าม AZ เพื่อไม่ให้มี single point of failure

สุดท้ายคือ virtualization ซึ่งทำให้ Cloud ขาย VM ได้ถูก x86 รุ่นเก่ามีคำสั่ง sensitive ที่ไม่ trap จึงเกิดวิธีแก้สามแบบ และแนวโน้มของทุกเรื่องคือย้ายงานจากซอฟต์แวร์ไปให้ฮาร์ดแวร์ (VT-x, EPT, SR-IOV) เมื่อทุกเครื่องรัน hypervisor ทั้ง data center ก็สั่งงานอัตโนมัติได้ ส่วน container เบาและเร็วกว่า VM เพราะใช้ kernel ร่วมกัน และด้วยเหตุผลเดียวกันจึงแยกกันได้ไม่เด็ดขาดเท่า

กับดักที่เจอบ่อยมีไม่กี่เรื่อง ping ใช้ ICMP ไม่ใช่ TCP หรือ UDP ส่วน Docker อยู่ระดับ OS ไม่ใช่ HAL ถ้าหลายเครื่องใช้โฟลเดอร์เดียวกันให้ตอบ File storage คำว่า VMM หมายถึง hypervisor live migration ทำได้เฉพาะตอนเครื่องต้นทางยังไม่พัง และ overcommit คือ RAM ที่ขายไปทั้งหมดหารด้วย RAM จริง
